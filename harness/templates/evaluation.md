# 验证与评测指南（Evaluation）

本文档是本项目**程序化验证体系**的总览与执行入口，贯穿新功能开发、对话纠偏、代码重构、需求变更、缺陷修复与线上进化回流的全生命周期。

> **概念与载体**：
> Evaluation 的核心是把「什么算做对了」程序化为可重复执行的自动裁判，**不绑定单一测试形态**——载体可以是单元测试、集成测试、黑盒/E2E 校验、评测基准或运行期脚本，按任务性质选用最直接可靠的载体。单元测试编写规范另见 [`docs/testing.md`](./testing.md)。

## 验证分层与载体映射

所有需求验证目标与对话中纠正的关键约束，均按可程序化程度分层并映射到本项目的实际载体：

| 层级 | 适用场景 | 本项目实际载体与路径 |
|------|----------|----------------------|
| **L1 确定性断言** | 算法/几何不变量、接口/CLI 契约、状态一致性、错误语义、渲染边界、性能硬预算 | `<如 tests/unit/、tests/integration/、e2e/ 或 evals/cases/>`（100% 程序化，硬门禁） |
| **L2 评测与评分** | 非确定性输出、生成/分类质量、检索准确率、Agent 路径（按需使用） | `<如 evals/benchmarks/ 固定数据集 + 评分脚本 + 通过阈值>` |
| **L3 最小人工核验** | 确实无法客观程序化的主观体验 | 显式记录在对应 `docs/design/<module>.md`，控制在最小集合 |
| **运行期验证** | 离线无法覆盖的线上真实流量/长周期指标（交接 [`docs/evolution/registry.md`](./evolution/registry.md)） | `<如 evals/runtime/ 可复跑查询脚本或监控命令>` |

> 优先复用项目既有的测试框架与目录；仅当存在独立的评测集、黑盒脚本或运行期验证脚本时，按需建立 `evals/` 目录集中存放。

## 结果判读规范

程序化验证面向 Agent 自闭环与无人值守回归设计：

- **退出码**：`0` 表示全部达标；非 `0` 表示存在未通过项。
- **失败诊断**：输出必须标明失败的目标/用例标识、预期条件、实际观察值及关键上下文，使 AI 能直接据此修复。
- **结构化摘要**（推荐）：L2 评测或批量验收输出 JSON/表格摘要（通过率、关键指标、与基线差值），便于跨提交与跨周期对比。

示例（L2 评测失败时的机器可读输出，供 Agent 直接定位修复）：

```json
{
  "target_id": "V-03",
  "passed": false,
  "metrics": { "accuracy": 0.86, "baseline": 0.90, "p95_ms": 310 },
  "threshold": { "accuracy_min": 0.90, "p95_ms_max": 500 },
  "failed_samples": [
    { "id": "S-17", "expected": "billing", "actual": "unknown", "reason": "keyword missed" }
  ]
}
```

示例（供 `evolution` 同口径复跑的运行期验证命令，退出码 `0` 表示达标，stdout 输出结构化指标）：

```bash
./evals/runtime/check_unknown_rate.sh --since 2026-11-16 --until 2026-11-23 --max-rate 0.05
```

## 全生命周期演进规则

验证资产随项目持续演化，变更权限与 `<AI_ENTRY>.md` 中的 `project-stage` 保持一致：

1. **目标可前置，也可随协作生长**：开工前能明确的验证目标先形式化并程序化；与 AI 对话协作中纠正的错误逻辑，当场补充为程序化验证锁死，不靠聊天记忆维持正确性。
2. **需求不变，裁判不动**：重构、性能优化或内部实现替换时，既有验证资产为只读回归裁判；全量通过即自动证明未破坏既有行为，无需人工逐项复判。
3. **需求变更，验证同步演化**：若用户明确变更对外行为，先按 `project-stage` 判定是否允许破坏既有契约（`greenfield` 直接同步更新；`confirm` 确认影响面后更新；`compatible` 严禁破坏既有验证，仅允许扩展），再同步更新 spec 与对应验证用例。
4. **排障与进化必须沉淀回归**：每次通过 [`docs/debugging/`](./debugging/registry.md) 修复故障或通过 [`docs/evolution/`](./evolution/registry.md) 落地改进，必须将对应失败模式沉淀为可复跑的回归验证，防止复发。
5. **禁止无依据降标**：任何阶段严禁为让代码“变绿”而删减/跳过既有验证、放宽阈值或用 mock 绕开待验证的核心逻辑。
