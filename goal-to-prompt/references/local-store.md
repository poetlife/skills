# 本地存储约定

## 定位记录库

按优先级选择一个库，不自动遍历所有历史目录：

1. 用户本次明确指定的记录库目录，仅作用于本次操作。
2. 环境变量 `GOAL_TO_PROMPT_HOME`。
3. `~/.config/goal-to-prompt/config.json` 的 `store_dir`。
4. 默认 `~/.local/share/goal-to-prompt`。

将 `~` 展开为用户主目录；本次给出的相对路径基于当前工作目录解析。环境变量和配置中的路径必须为绝对路径或 `~/` 开头，不能随项目工作目录变化。JSON 用结构化解析器读取，不通过 shell 执行配置内容。无效 JSON、无效目录类型或权限错误需报告实际问题，不悄悄改用另一个库。

用户要求“设置记录库目录”“以后存到……”时，将规范化绝对路径持久写入上述配置的 `store_dir`，保留其他字段。本次仅指定目录不代表修改持久配置。如果环境变量覆盖了配置，说明当前实际生效的路径。配置示意：

```json
{
  "store_dir": "/absolute/path/to/goal-library"
}
```

检索时库不存在就返回尚无记录，不创建文件。首次写入时创建所需目录。设置新目录不迁移旧库；只有用户要求搬迁时才另行处理。所有操作使用同一解析后的根目录，并在结果中给出实际记录路径。

## 文件与元信息

```text
<store_dir>/
  records/
    <record-id>.md
```

一类事情一份 Markdown，同一事情的不同处理方案放在正文中。正文是唯一内容来源，不另外维护易失配的索引。记录 ID 使用该事情的可读 slug，落盘前查重；不同事情重名时增加区分后缀。创建后不因标题变更而改 ID。ID 不含路径分隔符，新建文件必须位于库的 `records/` 内，不覆盖重名记录。

每份记录以 YAML frontmatter 开始，使用合法 YAML 序列和字符串，标题等自由文本由 YAML 序列化器输出或正确引用，避免冒号等字符破坏结构：

```yaml
---
id: "<事情的稳定 slug>"
title: "<要做的事情>"
summary: "<输入、输出及主要选择分支的摘要>"
aliases: ["<常见叫法>"]
tags: ["<所属领域>"]
capabilities: ["<处理能力>"]
technologies: ["<方案涉及的工具或技术>"]
status: active
created_at: "<实际创建时间，ISO 8601>"
updated_at: "<实际更新时间，ISO 8601>"
---
```

上面是字段模板，落盘时填入真实内容；没有别名或技术名称时使用空列表。`status` 为 `draft`（尚在整理）、`active`（供检索使用）或 `archived`（仅作历史参考），表示记录生命周期，不表示方案已被验证。适用条件、经验来源、验证范围和工具间接口保存在正文，每个方案可以有不同的证据强度。

旧记录缺少 `aliases` 时按空列表读取；旧项目任务记录仍可作为历史资料检索，但不得因其 `completed` 状态就将其全部方案认定为通用经验。只有用户要求整理时才抽取可复用方法，不批量自动迁移旧数据。

更新时保留 `id`、`created_at` 和正文中的既有来源，更新 `updated_at` 及实际变化的元信息。日期使用实际当前时间；标签和能力词使用自然语言，技术列表记各有效方案涉及的关键技术，不堆砌关键词。

## 检索与读写实现

存储职责是定位库、列举记录、按 ID 读取、新增或更新文件；检索职责是构造查询、筛选候选、检查适用性及返回来源。两者通过上述文件和元信息约定协作，不把搜索结果另存成第二套记录。

当前可直接使用文件工具和 `rg`：

- 列举 `<store_dir>/records/` 下的 Markdown 文件；先缩小候选范围，再读取全文。
- 使用 `rg -n -i -F` 的多个 `-e` 参数搜索目标、能力、标签、技术及正文，并限制到记录目录和 `*.md`；固定字符串模式避免用户输入被当作正则。命令参数必须正确引用，搜索词不能作为可执行 shell 内容。
- 精确 ID 查找直接读取对应文件并核对 frontmatter 的 `id`。列举或全文搜索还可发现元信息缺失的旧记录；标注缺失，不因缺字段而隐瞒命中，也不在只读检索中自动修复。
- `rg` 返回 1 表示无匹配；目录权限、读写失败等错误不能解释为没有相关记录。没有 `rg` 时使用可用文件搜索工具完成同样工作。
- 保存前读取现有文件并核对是否被更新，避免覆盖其他会话的新内容；保存后重新读取检查完整性与来源引用，并用 ID 和实际关键词确认可检索。失败时报告失败，不宣称保存成功。

以后更换存储后端时保留记录 ID、元信息语义和来源引用，替换此处的存取约定即可；目标拆解、方案迭代和提示词生成流程不依赖具体存储工具。
