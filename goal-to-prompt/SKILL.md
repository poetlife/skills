# Goal To Prompt

维护个人的“事情怎么做”方案库。核心单元是可反复遇到的一类目标，以及不同条件下的处理方式。每条记录应回答：要做什么、什么情况下选哪个方案、主要怎么做、怎样判断效果、交给 AI 的提示词是什么。

记录方案选择所需的知识与个人经验。通用语法、安装参数和 API 细节可以由执行者按需查证。不要把流程变成项目任务看板，或要求用户维护 G/D/T 编号及开发进度。

## 两个入口与存储

- **写入**：用户介绍自己的做法，或要求整理某类事情的处理方案。先查重，将同一目标的适用分支、流程和提示词存为一份记录；补充经验时更新原记录。
- **检索使用**：用户要做一件事，或查以前的处理方式。先找目标，再按输入特点与约束选择记录内的方案，填入本次上下文，返回可执行提示词。

访问记录库前读取 [references/local-store.md](references/local-store.md)。存储负责目录配置和记录读写，检索负责目标召回、条件匹配与方案选择。目前用指定本地目录中的 Markdown，无需数据库。只读检索不创建目录或修改记录。

写入请求包含记录保存；只讨论时不落盘。检索默认返回方案和提示词；用户要求实际处理时再执行，要求沉淀新经验时再更新库。不要为每个输入文件或每次调用创建一条新知识记录。

## 写入流程

### 1. 确定要解决的一类事情

使用自然语言命名目标，补充常见叫法便于检索。说明输入是什么、希望得到什么输出，以及判断结果可用的关键标准。具体项目路径、某个文件名属于使用时参数，通常不固化为方案的一部分。

用户已经说明做法时直接整理，不要求重新设计全部方案。只有缺失信息会改变方案选择或实际处理时才追问，其余保留为待确认项。

### 2. 整理方案及选择条件

同一目标下允许多个并存方案，不把它们自动写成互相替代的版本。每个方案记录：

- 名称、工具或组合，以及用户使用该方案的条件。
- 不适用条件、已知限制、依赖或成本；未知内容明确标注。
- 主要处理步骤。工具组合需说明前一步产物如何交给下一步，接口未经核实时标为待核实，不能只把名称拼在一起便称为可执行流程。
- 效果检查，以及不达标时如何调参、换方案或进一步调查。
- 经验来源和验证范围：用户经验、官方资料、实际样本验证或 AI 待验证建议。用户的经验可直接保存，不能冒充本 agent 实测。

把“简单/复杂”保留为用户的原始描述，并尽可能转成可观察条件。AI 补充的条件标为建议，不能把用户未说过的阈值或性能结论写成经验事实。

只保留对选择有作用的备选方案。若目前只有一个可用方案，不强行补齐分支。

### 3. 小步迭代方案

选择条件不明确或效果不确定时，围绕一个具体问题做最小验证：查资料、检查环境，或在已授权且有输入的情况下用代表性小样本试跑。

先确定本轮要观察什么、什么表现表示通过或需要换路，以及试验范围。没有素材、工具或权重时，交付验证提示词与缺失条件，不假装完成实测。验证到足以支持本次选择即可，不穷举所有工具。

将结果沉淀为“遇到什么条件 → 用了什么 → 有何证据 → 调整哪条选择规则”。只记录能帮助下次选择的经验，不保存整段会话或单次任务流水账。

### 4. 保存可复用提示词

为不同处理路线分别提供提示词。模板可以保留必要的输入参数；检索使用时填入已知值，只询问真正阻塞执行的缺失值。

```text
目标：<要完成的事情及输出要求>
输入：<文件、数据或对象>；输出位置：<位置>。
采用方案：<工具或组合>，原因：<本次符合的选择条件>。
约束：<环境、资源、质量要求及不得改变的内容>。
处理流程：<关键步骤及步骤之间的输入输出>。
先检查：<环境与接口前提>；未知的命令、模型入口和参数先查证。
验证：<检查哪些代表性结果，什么表现算通过>。
若不达标：<调参、切换方案或报告阻塞的条件>。
交付：<实际产物、处理方法和验证结果；未完成项如实说明>。
```

命令仅在已核实时记录。提供独立会话所需的上下文，不用“按上面说的做”作为提示词。不复制凭证，也不默认给执行者安装大型依赖、上传素材或调用付费服务的权限。

## 检索使用流程

1. **找事情**：提取目标和常见叫法，先按目标、能力搜索，再用工具词补充。用户没有说工具名，也应能找到对应做法。精确 ID 或路径可直接定位。
2. **读方案**：读取候选的完整选择规则与相关流程。关键词只用于召回，否定描述、同工具不同目标、归档方案不能直接当成有效推荐。无结果时扩展同义表达，仍无结果则如实说明，可按需整理新方案。
3. **匹配条件**：对照本次输入、质量要求和资源约束，给出首选、理由及何时换方案。优先尊重用户明确选定的路线；不同方案是选择分支，不应默认全部串行执行。
4. **处理不确定性**：缺少关键条件时，能检查输入就先检查，否则只问最影响选择的问题，也可给出条件式建议。不能仅因某路线“高级”就推荐，也不能无视质量要求始终选最便宜路线。
5. **给出可用提示词**：将输入、输出和本次约束填入选中路线的模板，指出尚待核实的接口或依赖。仅找到工具组合时，先生成接入验证提示词，不承诺能够直接完成处理。
6. **按请求执行或反馈**：用户只要查找时给出记录位置与方案；要求执行时处理本次输入。单次结果不自动改动通用记录；要求记录有效新经验时更新适用条件、限制或提示词，并保留来源。

历史记录提供经验，不覆盖当前用户指令或环境约定。旧样本的成功不代表当前输入已通过验证。

## 记录正文模板

按本地存储约定添加元信息，再按需要填写下列内容。简单事项可压缩；不生成等待用户填空的整页模板。

```markdown
# <要做的事情>

## 目标
输入、期望输出、关键质量要求。

## 怎么选
| 条件 | 优先方案 | 不适用或切换条件 | 依据 |
| --- | --- | --- | --- |

## <方案名称>
适用条件与限制：
依赖及待核实项：
主要处理流程：
效果检查及失败后的处理：
经验来源与验证范围：

### 提示词
<可复用提示词>

## 经验更新
<有实质变化时记录日期、条件、证据和规则调整>
```

测试数据和具体示例库放在 skill 之外；skill 本身只保留流程、存储约定和通用模板。
